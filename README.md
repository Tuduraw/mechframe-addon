# Mech Frame

[Tudur's Vehicle Mod](https://github.com/Tuduraw/tudursvehiclemod)(`tudursvehiclemod`)のアドオンMODです。
パーツを組み替えて作る「メックフレーム」を追加します。

- **高速メカアクション**: マウスで機体を旋回させながらWASDで全方向に移動します。ブースト移動、入力を離した瞬間の急停止、
  瞬間的な横移動(クイックブースト)、ジャンプとホバーがあり、これらはEN(エネルギー)を管理しながら使います。
- **多様な脚部**: 二脚、逆関節、タンク(履帯)、四脚、六脚(蜘蛛型)、ホバー(特殊規格)の6種類があります。脚は2ボーンIKで地形に接地し、
  脚の種類ごとの歩容で歩きます(二脚は交互、四脚はトロット、六脚はトライポッド歩容)。
- **変形**: 同じ「変形セット」のパーツで組んだ機体は、Vキーで戦闘機形態に変形します。地上でも空中でも変形できます。
  変形中も各パーツは関節でつながったまま動きます。変形のしかたが違う3機があります(下の「変形機の比較」)。
- **アセンブリ**: 頭部・コア・腕部・脚部・ブースター・武装4か所を組み替えると、性能と見た目が変わります。
  組み替えはガレージで行い、使えるのはガレージに入れたパーツだけです。
- **メック製作台と拡張パック**: パーツはメック製作台で、手持ちの材料を使って作ります。パーツ・機体・レシピは
  `tudursvehiclemod-addons/` に置く拡張パックで追加できます。拡張パック「Frontier Frames」(4社・42パーツ・標準機12機、
  ホバー脚や武器内蔵腕などの特殊規格を含む)を `packs/mechframe_expansion1` に同梱しています。

前提MODの公開API(`AbstractVehicleEntity`のオーバーライド可能なメソッド、
`VehicleConverterTargets`、`HudVariableProvider`など)を使っています。前提MODへの変更は必要ありません。
前提MOD側の仕様に合わせる必要があった箇所はアドオン側で対応しています(後述の「前提MODとの関係」)。

このMODの設計・コード・3Dモデル・テクスチャ・効果音は、AnthropicのAI「Claude」を使って作成しました。
モデルは添付ツール meshkit を使ったPythonスクリプト(`tools/mechgen`)で生成しています。
テクスチャもスクリプトで描き、効果音はスクリプトで合成しました。他者が権利を持つデータは使っていません。

## 動作要件

- Minecraft 1.21.11
- Fabric Loader 0.18 以降、Fabric API
- tudursvehiclemod 1.0.5 以降

## 入手と組み替えの流れ

1. **機体**: 前提MODの車両コンバーターで「Mech Frame」ページを選ぶか、Tier 1〜5の「Mech Frame」スポナーを使います。
   選んだプリセットの機体が出現します(下表)。
2. **パーツ**: パーツは**メック製作台**で作ります(後述)。Tier別の機体キット(スポナー)も製作台で作れます。
   クリエイティブタブ「Mech Frame」にも全パーツがあります。
3. **ガレージ**: ガレージブロック(鉄ブロック・レッドストーンブロック・作業台・金床)を置き、クラフトしたパーツを
   収納欄(54スロット)に入れます。
4. **組み替え**: ガレージから16ブロック以内にいる、誰も乗っていない機体を右側のパネルで組み替えます。
   - パネル上部の「< >」で対象の機体を選び、取り付け箇所(9か所)を選ぶと候補が並びます。
   - 候補は、その機体の**標準パーツ**(プリセットの構成。常に使え、費用もかからない)と、**ガレージに入っている
     互換パーツ**だけです。候補にカーソルを合わせると、変更後の性能が現在の値と並んで表示されます(改善は緑、悪化は赤)。
   - ガレージのパーツを取り付けるとガレージから1個減ります。外したパーツが標準パーツでなければガレージに戻ります。
     ガレージが満杯で戻せないときは組み替えません。
   - 標準パーツはアイテムとしては取り出せませんが、いつでも元に戻せます。「Reset to stock」で全箇所を標準に戻します
     (付けていたパーツはガレージに戻ります)。
   - 組み替えは機体ごとに保存されます。耐久値(AP)は割合を保ったまま新しい最大値に合わせます。

## 操作

### ロボット形態

| 操作 | 既定キー | 内容 |
|---|---|---|
| 旋回・照準 | マウス | 機体(胴体)が視点の方向へ脚部の旋回速度で向きを変えます |
| 移動 | W / A / S / D | 視点に対して全方向に移動します。入力を離すと急停止します |
| ブースト | 左Ctrl(押すたびにオン/オフ) | ブースターの速度で移動します。地上ではENを消費せず、空中ではENを消費します。オンの間は画面上部に「BOOST」と出ます |
| クイックブースト | X、または方向キーの2度押し | 入力方向へ瞬間的に加速します(約10ブロック)。ENを消費します |
| ジャンプ / ホバー | Space | 押すとジャンプします。空中で押し続けるとENを消費して上昇・滞空します |
| 変形 / ターボ | V | 変形セットで揃えた機体は戦闘機形態に変形します。変形できない機体ではターボモードのオン/オフです(下記) |
| 左の武器を使う | 左クリック | 左側で選んでいる武器(左腕か左肩)を撃ちます。近接武器なら斬りかかります |
| 右の武器を使う | 右クリック | 右側で選んでいる武器(右腕か右肩)を撃ちます |
| 左の武器の切り替え | Z | 左の武器を、左腕と左肩で切り替えます。選んだ側が空のときは、もう一方を使います |
| 右の武器の切り替え | C | 右の武器を、右腕と右肩で切り替えます |
| ロックオン | 前提MODのターゲット指定キー(B) | FCSの候補(オレンジの枠)をロックします(赤い枠)。もう一度押すと解除します |

キーはすべて「操作設定 > Mech Frame Addon」で変更できます。
武器の操作はこのアドオンのキーだけで行います。機体に乗っている間は、前提MODの「武器の発射」「武器の切り替え」キーは無視されます(ほかの乗り物では今までどおり使えます)。
HUDでは、各側で選んでいる武器に「>」と使うキーが表示されます。乗り込んだときは左右とも腕の武器が選ばれています。
方向キーの2度押しによるクイックブーストは、`config/mechframe-client.json`の`"double_tap_quick_boost": false`で無効にできます
(Xキーは常に有効です)。

#### 近接武器(WM-K1 Laser Blade)

腕に付ける近接武器です。その腕のキーを押すと、ロックした目標(なければFCSの候補)へ踏み込み、腕を外側へ振りかぶってから横に薙ぎ払います。
間合い(機体の前面から約4m)の内側で、正面の左右70°以内にいるものすべてに当たります。目標がいないか遠いときは正面へ踏み込み、途中に何かあればそこで止まります。
1回ごとにENを消費し、振り終えてから次に振れるまで少し時間がかかります(HUDの READY が目安)。戦闘機形態とターボ中は使えません。

ブーストを押している間だけにしたい場合は、`config/mechframe-client.json`の`"boost_toggle": false`にします。

#### ターボモード(変形できない機体)

変形できない機体でVキーを押すと、ターボモードになります(もう一度押すと解除)。

- 機体を前へ倒し、脚を胴体と一直線に後ろへ流した姿勢で、ブースト速度の約2.4倍(標準的な機体で時速約180km)で前方へ飛び続けます。
  視点の上下で上昇・降下、マウスで旋回します。Sキーで減速、A/Dでわずかに横へずれます。
- 燃料を通常の約3倍の速さで消費します。ENは使いません。燃料が尽きると解除されます。
- 加速・減速と旋回(通常の約0.3倍)が鈍く、クイックブースト・ジャンプ・ホバーは使えません。
- 解除すると通常のロボット形態に戻り、そのまま落下を始めます(ホバーで立て直せます)。

#### 戦車式操作(タンク脚)

`config/mechframe-client.json`の`"tank_controls": true`で、タンク脚の機体を戦車のように操作できます
(既定は`false`。ファイルは初回起動時に作られます。変更後はゲームの再起動が必要です)。

| 操作 | キー | 内容 |
|---|---|---|
| 前進・後退 | W / S | 下部車体の向きに沿って進みます |
| 車体の旋回 | A / D | 下部車体がその場で旋回します(超信地旋回) |
| 砲塔(上半身)の旋回 | マウス | 上半身は車体と関係なく視点の方向を向き、360度回ります |
| クイックブースト | X または方向キー2度押し | 車体に対する方向へ跳びます(A/Dの2度押しで車体の真横へ) |

タンク脚以外の機体や戦闘機形態では、この設定に関係なく通常の操作です。

### 戦闘機形態

| 操作 | 既定キー | 内容 |
|---|---|---|
| ピッチ / ヨー | マウス | 機首の向きを変えます。視点は機首に固定されます(前提MODのフリールックキーで解除できます) |
| ロール | A / D | 地上ではタキシング中の旋回になります |
| スロットル | W / S | 上げる / 下げる |
| アフターバーナー | 左Ctrl | ENを消費します |
| 横回避(ジンク) | X | 横方向へ瞬間的に回避します |
| 変形(ロボット形態へ) | V | 空中で変形すると、それまでの速度を保ったまま落下を始めます。Spaceのホバーで姿勢を立て直せます |

戦闘機形態の飛行は前提MODの航空機に近い挙動です。失速があり、上昇すると減速し、降下すると加速します。

## パーツと性能

取り付け箇所は9か所です。コア・腕部・脚部は必須です。

| 箇所 | 主な性能 |
|---|---|
| 頭部 | FCSのロック距離・ロック角、安定性 |
| コア | EN容量・EN回復量・回復開始までの遅れ、防御、燃料。変形セットのコアは戦闘機形態の性能も持ちます |
| 腕部 | 腕部積載量、照準速度、反動制御 |
| 脚部 | 種類、積載量、歩行速度、ジャンプ力、旋回速度、段差、グリップ(加減速の鋭さ) |
| ブースター | ブースト速度、クイックブーストの速度・EN消費・間隔、ホバー推力・EN消費 |
| 右腕 / 左腕 | 腕用の武器(ライフル、機関銃、バズーカ、パルスレーザー、ガンポッド、レーザーブレード) |
| 右肩 / 左肩 | 背中用の武器(ミサイルポッド、肩部キャノン、背部ガトリング) |

- **重量と積載量**: 脚部以外の総重量が脚部の積載量を超えると過積載(HUDに「OVERWEIGHT」と表示)になり、
  速度・ジャンプが落ち、クイックブーストのEN消費が増えます。積載量の範囲内でも、重い機体ほどクイックブーストと
  旋回がわずかに鈍くなります。
- **腕部積載量**: 両腕の武器の合計重量が腕部の積載量を超えると、照準速度が落ちます(「ARM OVERLOAD」と表示)。
- **AP**: 全パーツの装甲値の合計が機体の最大耐久値になります。
- **EN**: ENを使い切るとオーバーヒートし、回復が始まるまでの時間が長くなります。
- **ブースターなし**: ブースター箇所は空にできます。その場合、ブースト移動は歩行の1.4倍までになり、ホバーとクイックブーストは使えません。
- **安定性**: 頭部とコアの安定性の積です。高いほど、加減速・横移動での機体の傾きと、着地の衝撃による画面の揺れが小さくなります。
- **変形条件**: 頭部・コア・腕部・脚部・ブースターがすべて同じ変形セットで、コアが戦闘機形態の性能を持つことが条件です。
  ガレージの性能表示に「Transform: OK」と表示されます。武器はどれでも構いません。

### FCS(照準補正)

照準の近くにいる敵(ロック距離・ロック角の範囲内で、視線が通っている最も近い対象)がソフトロックの候補になり、
オレンジの枠と名前・距離で表示されます。腕や肩の武器は、候補またはロックした目標を狙います。
目標の移動と弾速・弾の落下から未来位置を計算し、銃口と旋回軸のずれも補正します。候補がないときは照準の先を狙います。
ロックした目標は、照準から外れても距離の1.5倍まで追い続けます。

## HUD

前提MODのHUDスクリプト(`assets/mechframe/hud/mech_hud.txt`)で表示します。
小さな画面(GUI拡大後427×240)でもホットバーと重ならないように配置しています。

- 中央下: ENゲージ、BOOST / HOVER、クイックブースト可能(QB)、オーバーヒート(EN OUT)
- 左: 機体名、AP、速度、高度、各種警告
- 右: 4か所の武器と残弾(近接武器は READY / ----)。各武器を使うキーの名前も表示します
- 上: FCSの目標名・距離・耐久、変形中の形態表示

このアドオン独自のHUD変数は`mf_`で始まります(`mf_en`、`mf_en_rto`、`mf_boost`、`mf_hover`、`mf_qb_ready`、
`mf_overheat`、`mf_jet`、`mf_lock`、`mf_soft`、`mf_tgt_dist`、`mf_ra_ammo`など。一覧は`MechHud.java`にあります)。

## メック製作台とレシピ

パーツと機体キットは、作業台ではなく**メック製作台**(`mechframe:fabricator`)で作ります。

- 右クリックで製作画面が開きます。左に作れるものの一覧(分類ごと、ホイールでスクロール、上の欄で名前検索)、
  右に選んだものの性能と材料が「持っている数 / 必要な数」で並びます。足りない材料は赤で表示されます。
- 「製作」を押すと、インベントリ全体から材料を取り、完成品を渡します(いっぱいなら足元に落とします)。
- クリエイティブモードでは材料なしで作れます。
- 製作台から8ブロック以内にいる間だけ作れます。
- 製作台自体は作業台で作ります: `IRI` / `PCP` / `SSS`(I = 鉄インゴット、R = レッドストーンブロック、P = ピストン、
  C = 作業台、S = 滑らかな石)。

| Tier 4 | 鉄ブロック×8、ダイヤモンド×4、レッドストーンブロック×4 |

## パーツ・機体の追加(データ駆動)

パーツ・機体・製作台のレシピはすべてJSONで定義しています。データパック、ほかのMODのjar、前提MODの`tudursvehiclemod-addons/`
フォルダのどこに置いても読み込まれます。`/reload`で再読み込みできます。サーバーが読み込み、接続時にクライアントへ送ります。

### 拡張パック(`tudursvehiclemod-addons/<パック名>/`)

パーツと機体を追加する拡張パックは、前提MODのアドオンと同じフォルダ構成で作れます。データパックやリソースパックは不要です。
例として拡張パック「Frontier Frames」(`mechframe_expansion1`、名前空間`mfx`)を同梱の`packs/`に置いています。

```
tudursvehiclemod-addons/<パック名>/
  data/<ns>/mech_parts/<id>.json         パーツ(下記)。"recipe" を書けば製作台で作れる
  data/<ns>/vehicles/<id>.json           機体(プリセット。下記)。スポナーの一覧に出る
  data/<ns>/mech_recipe/<名前>.json      製作台のレシピ(パーツ以外の物も作れる)
  assets/<ns>/models/obj/parts/<id>.obj  モデル
  assets/<ns>/textures/vehicle/<...>.png テクスチャ(アドオンフォルダでは textures/vehicle の下だけ読まれます)
  assets/<ns>/weapons/<名前>.txt         武器ファイル(前提MODの形式)
```

### 製作台のレシピ

パーツのJSONに`"recipe"`を書くと、そのパーツのレシピになります(完成品はそのパーツ)。

```json
"recipe": { "ingredients": [ {"item": "minecraft:iron_ingot", "count": 4}, {"item": "minecraft:feather", "count": 2} ] }
```

パーツ以外の物や、別の名前のレシピは`data/<ns>/mech_recipe/<名前>.json`に書きます。同じIDのレシピファイルがあれば、
パーツ内のレシピより優先されます。

```json
{
  "category": "frames",
  "result": {"item": "mechframe:mech_spawner_t3"},
  "ingredients": [
    {"item": "minecraft:iron_block", "count": 8},
    {"tag": "minecraft:planks", "count": 4},
    {"part": "mfx:cr_facet"}
  ]
}
```

| キー | 既定値 | 内容 |
|---|---|---|
| `result` | パーツ内のレシピではそのパーツ | `{"part": "<パーツID>"}` または `{"item": "<アイテムID>"}`、と`count`(既定1) |
| `ingredients` | 必須 | 材料。`item`(アイテムID)、`tag`(アイテムタグ、`#`なし)、`part`(パーツID)のどれか1つと`count`(既定1) |
| `category` | 完成品のパーツの箇所(`head`など)、それ以外は`items` | 一覧での分類。`gui.mechframe.fab.category.<分類>`の翻訳があれば表示に使います |
| `order` | パーツのTier | 分類内の並び順 |

材料やパーツが見つからないレシピは読み込まずにログへ警告を出します。

### 特殊規格

| 規格 | 書き方 | 内容 |
|---|---|---|
| ホバー脚 | 脚の`"type": "hover"`(`chains`なし、`pelvis_groups`にスカートのグループ) | 脚がなく、地面から浮いたスカートで滑るように進みます。ジャンプはできず(スペースはホバー)、旋回で横滑りし、キーを離しても少し滑り続けます。スカートは上半身の向きに遅れて回り、横滑りの向きに傾きます |
| 武器内蔵腕 | 腕部の`"integrated": {"r_arm": "<武器パーツID>", "l_arm": "..."}` | その腕の武器箇所は常に内蔵武器になり、ほかの武器を付けられません(ガレージでは「内蔵」と表示)。内蔵武器のパーツは`"mount": "integrated"`にして、レシピを書かないでください(単体では取り付けられません) |
| 突き型の近接武器 | `stats.melee`に`"style": "thrust"` | 振りかぶらずに腕を引いてから真っすぐ突き出します。`arc`を狭くすると正面だけに当たります |


### パーツ: `data/<namespace>/mech_parts/<id>.json`

パーツIDは`<namespace>:<ファイル名>`です。座標はモデル空間(+X = 左、+Y = 上、+Z = 前、1 = 1ブロック)で書きます。

```json
{
  "slot": "legs",                      // head / core / arms / legs / booster / weapon
  "display_name": "LG-K1 Stride",
  "maker": "Kestrel Dynamics",
  "tier": 1,
  "transform_set": "falcon",           // 省略可。変形セット名
  "weight": 16.0,
  "armor": 260,
  "model": "mechframe:models/obj/parts/lg_stride.obj",
  "texture": "mechframe:textures/part/lg_stride.png",
  "points": { "hip": [0, 2.9, 0] },    // 接続点(箇所ごとに下表)
  "stats": { ... },                    // 箇所ごとの性能(下表)
  "jet_pose": { ... }                  // 変形セットのみ。OBJグループごとの戦闘機形態での配置
}
```

| 箇所 | points | stats の主なキー |
|---|---|---|
| head | `top` | `lock_range`, `lock_cone`, `stability` |
| core | `neck`, `shoulder_l`(`shoulder_r`), `back`, `back_l`(`back_r`), `seat`, `eye`(`jet_eye`: 戦闘機形態の視点。省略時は`eye`) | `en_capacity`, `en_recharge`, `recharge_delay`, `defense`, `fuel`, `stability`, `jet`{`max_speed`, `acceleration`, `turn_speed`, `stall_fraction`, `afterburner`, `afterburner_cost`, `collision_height`} |
| arms | `elbow`, `grip` | `load_limit`, `aim_speed`, `recoil_control`, `integrated`(武器内蔵腕。上記) |
| legs | `hip` | `type`(`biped` / `reverse_joint` / `tank` / `quad` / `hexapod` / `hover`), `load_limit`, `walk_speed`, `boost_multiplier`, `jump`, `turn_rate`, `step_height`, `traction`, `qb_multiplier`, `hover_multiplier`, `collision_width`, `step_length`, `step_lift`, `step_ticks`, `core_tilt`(コアの前傾、度), `pelvis_groups`, `chains`, `wheels` |
| booster | — | `boost_speed`, `qb_speed`, `qb_cost`, `qb_cooldown`, `hover_thrust`, `hover_cost`, `air_boost_cost`, `nozzles` / `jet_nozzles`([{`pos`, `dir`, `size`}]) |
| weapon | `muzzle` | `weapon`(前提MODの武器ファイル名), `mount`(`arm` / `back` / `any` / `integrated`), `projectile_item`, `recoil_distance`, `fcs`, `min_yaw` / `max_yaw` / `min_pitch` / `max_pitch`, `melee`(近接武器。下記) |

- 脚の`chains`は1本ごとに、OBJグループ(`upper` / `lower` / `foot`、多脚は付け根の`coxa`と`coxa_pivot`)、
  関節の位置(`hip` / `knee` / `ankle`)、膝の向き(`pole`)、2関節の脚では中間のOBJグループ`mid`と2つ目の関節`knee2`
  (`upper`: hip→knee、`mid`: knee→knee2、`lower`: knee2→ankle。`pole`はknee2の向き)、歩容グループ(`group`)と位相(`phase`)を書きます。
  関節の位置はモデルの静止姿勢から読み取ります。
- タンク脚は`wheels`([{`group`, `pivot`, `radius`}])に転輪のグループを書きます。転輪は走行距離に合わせて回転します
  (`radius`が小さい上部転輪・誘導輪ほど速く回り、履帯の速さがそろいます)。
- `jet_pose`はOBJグループ名ごとに`{"pos", "quat"(または"rot"), "delay", "parent", "joint"}`を書きます。
  `pos`と`quat`(x, y, z, w)、または`rot`(度、Ry·Rx·Rz)が戦闘機形態での配置です。`parent`(`"core:core"`のような
  「箇所:グループ」)と`joint`(自分のモデル座標での関節の位置)を書いたグループは、変形中も親に対して関節を中心に動くので、
  親から離れません。`delay`は動き始めを遅らせる量(0〜1)です。
- 腕部のOBJは、`l_`/`r_`で始まるグループが左右の腕です。肩(コアの`shoulder_l`)を原点に作り、腕全体が照準の方向を向きます。
- 右側の接続点(`shoulder_r`、`back_r`)を省略すると、左側をX方向に反転した位置になります。
- 武器の性能(威力・弾速・連射など)は、前提MODの武器ファイル(`assets/<ns>/weapons/<名前>.txt`)に書きます。
- 近接武器は武器ファイルを使わず、`stats.melee` に性能を書きます(腕用のみ):
  `damage`(威力), `reach`(機体の前面からの間合い m), `arc`(正面からの左右の角度), `lunge_speed`(踏み込みの速さ ブロック/tick),
  `lunge_range`(この距離までの目標に向かって踏み込む m), `en_cost`(1回の消費EN), `cooldown`(次に振れるまでのtick)、
  `style`(`slash` = 横に薙ぐ(既定) / `thrust` = 突き)。
  機体に当てたときは、1発あたりの被ダメージ上限(車両JSONの`armor_max_damage`)を超えて通るよう、数回に分けて当てます。

### 機体(プリセット): `data/<namespace>/vehicles/<id>.json`

前提MODの車両JSONに、`"entity_type": "mechframe:mech"`と`"mechframe"`オブジェクトを追加します。
寸法・武器・座席などはパーツから自動で生成するので、書かなくて構いません。

```json
{
  "entity_type": "mechframe:mech",
  "spawn_item": { "display_name": "KD) Striker", "tier": 1 },
  "hud": "mech_hud",
  "mechframe": {
    "assembly": {
      "core": "mechframe:cr_swift", "head": "mechframe:hd_lark", "arms": "mechframe:am_talon",
      "legs": "mechframe:lg_stride", "booster": "mechframe:bs_zephyr",
      "r_arm": "mechframe:wa_rifle", "l_arm": "mechframe:wa_rifle", "l_back": "mechframe:wb_missile"
    }
  }
}
```

## 前提MODとの関係

- 機体は`AbstractVehicleEntity`を継承した独自エンティティです。`getDefinition()`は、組み合わせごとに
  `VehicleDefinition`を合成して返します。当たり判定のメッシュも、組み合わせごとに生成して前提MODのキャッシュに登録します。
- 前提MODは武器とその旋回パーツを**武器名**で対応付けます。そのため、両手に同じ武器を持つと、左手の武器が
  右手の照準で撃たれてしまいます。このアドオンでは取り付け箇所ごとに別名(`mf_burst_rifle#l_arm`)で登録し、
  武器ファイルの読み込み時に`#`以降を取り除くことで解決しています(`WeaponStatsLoaderMixin`)。`#`を含まない
  ほかの車両の武器名には影響しません。
- そのほかの前提MODへのmixinは、private static フィールドを読むアクセサー2つだけです。

## 開発

- ビルド: 前提MODを`./gradlew publishToMavenLocal`でローカルMavenに公開してから、このプロジェクトで`./gradlew build`。
- モデル・テクスチャ・レシピなどの生成: `tools/mechgen`(meshkit 0.4.0 が必要。形状の関数は`meshkit.mech`)。
  拡張パック「Frontier Frames」は`tools/mechgen/packs/mfx/build_pack.py`で`packs/mechframe_expansion1/`に生成します。
  `python build_all.py`でパーツ、`python gen_resources.py`で機体JSON・武器・言語ファイル・HUD、
  `python gen_sounds.py`で効果音を生成します(ffmpegが必要)。
  機体はどれも約3,400〜4,850三角形(上限5,000)、テクスチャは512×512です。
  `build_all.py`は、全機体の組み立て状態と変形途中(25/50/75/100%)で浮いたパーツがないかを検査します。
- 自動プレイテスト(開発用): `./gradlew runClient -Pdevtest=<basic|falcon|swallow|manta|legs|gait|turn|hexboost|turbo|tank|garage>`。
  `run/saves/devtest`のワールドで機体の出現・搭乗・キー操作・変形・組み替え・射撃を自動で行い、
  `run/devtest.log`に挙動を記録して`run/screenshots`に画面を保存します。`-Pdevtest`なしのビルドには含まれません。
- 設計や技術的な知見は [DEVELOPMENT_NOTES.md](DEVELOPMENT_NOTES.md) にまとめています。
